    Insert the following block AFTER the existing `// MARK: - Cross-VM bridge` section (i.e., after `gotoCountdown(_:)` at line 140) and BEFORE the existing `// MARK: - Active session routing` section (line 142). Keep all existing methods unchanged.

    ```swift

        // MARK: - SHL-04 deep-link routing

        /// Handle an incoming `deluludetox://` URL delivered by SwiftUI's
        /// `.onOpenURL` modifier on `AppRootView`. Per CONTEXT §D-09 / §D-10:
        ///   - `deluludetox://session/active` + active session present → countdown.
        ///   - `deluludetox://session/active` + no active session → silent home (destination = nil).
        ///   - `deluludetox://` (root / fallback shield) → destination = nil.
        ///   - Any other scheme → no-op (defensive guard).
        ///
        /// The "session just completed, success not yet shown" branch in D-10 is
        /// handled automatically by the existing `handleHistory()` observer
        /// (Plan 03-06 deliverable) — handleDeepLink only needs to clear destination
        /// in the "no active session" branch and let the observer pick up.
        func handleDeepLink(_ url: URL) async {
            guard url.scheme == "deluludetox" else {
                logger.info("deeplink ignored scheme=\(url.scheme ?? "nil", privacy: .public)")
                return
            }

            // Root URL (or any non-session host) → clear destination.
            guard url.host == "session", url.path == "/active" else {
                logger.info("deeplink root path=\(url.path, privacy: .public)")
                destination = nil
                return
            }

            // session/active path — check current active session.
            let active = await currentActiveSession()
            if let active {
                logger.info("deeplink → countdown id=\(active.id.uuidString, privacy: .public)")
                // Reuse handleActive() routing logic to avoid double-instantiating
                // CountdownViewModel when one already exists for this id.
                handleActive(active)
            } else {
                logger.info("deeplink session/active but no active session — silent home")
                destination = nil
            }
        }

        /// Synchronous-style read of the current active session value via
        /// `withCheckedContinuation` over `observeActive().first()`. Mirrors the
        /// pattern in `FinalizeSessionFromMarkerUseCase.currentActive()`
        /// (Phase 3 Plan 03-03 deliverable). Used by `handleDeepLink` to decide
        /// routing without subscribing twice to the publisher.
        private func currentActiveSession() async -> SessionRecord? {
            await withCheckedContinuation { continuation in
                var cancellable: AnyCancellable?
                cancellable = observeActive()
                    .first()
                    .sink { value in
                        continuation.resume(returning: value)
                        cancellable?.cancel()
                    }
            }
        }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External app → DeluluDetox via `deluludetox://` URL | Any app on the device can open `deluludetox://...` URLs. URL contents are attacker-controlled. |
| `.onOpenURL` closure → HomeViewModel | URL is parsed in handleDeepLink before any state mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Spoofing | Malicious app sends crafted `deluludetox://` URL to fake "active session" route | mitigate | handleDeepLink reads the actual `activeSessionPublisher` value (from SessionRepository, the sole writer of session state). The URL only chooses between two destinations — both inside the app's own navigation graph. An attacker can't fabricate a session that doesn't exist. Acceptance: `currentActiveSession()` is the sole source of truth, never trusts URL params. |
| T-04-04-02 | Tampering | URL with embedded path traversal (`deluludetox://session/active/../etc`) tricks router into wrong destination | mitigate | Router uses STRICT equality `url.path == "/active"` — anything else falls through to `destination = nil`. No path concatenation, no template substitution. Acceptance criterion: `grep -c "url.path ==" HomeViewModel.swift` returns 1. |
| T-04-04-03 | Information Disclosure | Logger leaks URL contents to Console.app | accept | Logger logs `url.path` and `url.scheme` (both opaque app-controlled paths) and the `id.uuidString` of the active session (already logged elsewhere in HomeViewModel). All `.public`-safe. |
| T-04-04-04 | Spoofing | Another app registers `deluludetox://` first | accept | iOS resolves first-installed-wins. Documented in RESEARCH.md Security Domain. Universal Links (post-MVP) is the canonical mitigation. |
| T-04-04-05 | Denial of Service | Adversarial app spams `deluludetox://` URLs to exhaust HomeViewModel responsiveness | accept | Each URL triggers one synchronous publisher read (~µs) + one destination assignment. iOS already throttles `.onOpenURL` deliveries. No mitigation needed for MVP. |
| T-04-04-06 | Elevation of Privilege | Deep link bypasses session-cancel guards (QSN-05 from Phase 3) | mitigate | handleDeepLink only navigates — it does NOT call EndSessionUseCase or any session-mutating UC. Navigation alone cannot cancel a session. Acceptance: `grep -c "endSession\|cancelSession\|finalize" HomeViewModel.handleDeepLink` returns 0. |
</threat_model>
