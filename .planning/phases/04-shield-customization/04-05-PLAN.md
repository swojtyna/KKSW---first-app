    **Prerequisites:**
    - A physical iPhone running iOS 26.0 or later.

    **Step 1 — Build + install on device.**
    Use XcodeBuildMCP:
    ```
    XcodeBuildMCP list_devs           # find your physical device UUID
    XcodeBuildMCP build_dev_proj --scheme DeluluDetox --device-id <your-uuid>
    XcodeBuildMCP install_app_device --app-path <built .app path> --device-id <your-uuid>
    XcodeBuildMCP launch_app_device --bundle-id com.kksw.DeluluDetox --device-id <your-uuid>
    ```

    **Step 2 — SHL-01 Branded shield (active session branch).**
    1. In DeluluDetox, start a 15-minute quick session (Phase 3 flow) blocking a known app (e.g. Safari).
    2. Put DeluluDetox in background.
    3. Tap the blocked app icon (e.g. Safari).

       - Icon: white `hand.raised.fill` SF Symbol visible (yes/no).

       - Secondary button: `"Zamknij"` in system blue (yes/no).
       - Screenshot: attach inline or paste path.

    1. With the shield still visible, tap the primary `"Zobacz ile zostało"` button.

       - DeluluDetox foregrounds (yes/no). ← Key question — confirms Plan 01 spike.

    1. Put DeluluDetox in background, tap the blocked app again, shield reappears.

       - Behavior: shield dismisses, user lands on home screen (yes/no).
       - DeluluDetox did NOT foreground (yes/no — expected: NO foreground).

    **Step 5 — SHL-04 Deep link without active session.**
    1. Quit DeluluDetox fully (swipe up in app switcher).
    2. Open Console.app on the Mac, filter to device + subsystem `com.kksw.DeluluDetox`.
    3. From Terminal: `xcrun simctl openurl <device-uuid> deluludetox://session/active` — this MAY not work on a physical device (simctl is simulator-only). Alternative: in Safari on the device, type `deluludetox://session/active` in the address bar, tap Go.
    4. Record:
       - DeluluDetox opens (yes/no).
       - Landing screen with no active session: home (destination = nil expected) (yes/no).
       - No crash (yes/no).
    5. Now start a session and repeat (with DeluluDetox backgrounded, not quit). Open Safari `deluludetox://session/active`. Record:
       - Landing screen: countdown view (yes/no).

    **Step 6 — SHL-02 Fallback shield.**

    Triggering the fallback is TRICKY — it requires the shield to render when `active_session.json` is missing or unparseable. Two options:

    **Option A (recommended, minimal invasive):** After a session ends naturally (wait for timer or use `/End Session` if such affordance exists), the session file is cleaned up. If a blocked app is still shielded during a brief race window, its shield will render the fallback. In practice this is hard to catch — prefer Option B.

    **Option B (destructive but controlled):** Use `devicectl` or Xcode's "Device Container" inspector:
    1. With an active session running, use Xcode → Window → Devices and Simulators → DeluluDetox device → Installed Apps → DeluluDetox → gear icon → "Download Container...".
    2. Edit the downloaded container: delete the `active_session.json` file inside `AppGroup/group.com.kksw.DeluluDetox/`.
    3. Re-upload the container via the same inspector: "Replace Container...".
    4. Tap the blocked app icon while the ManagedSettings store still has the shield active.

    Record:
    - Fallback shield renders with brand design (violet, icon, two buttons) — NOT Apple default shield (yes/no).
    - Title: `"Zablokowane"` (yes/no).
    - Subtitle: `"Zamknij i zrób coś mądrzejszego."` (yes/no).
    - Primary button: `"Otwórz DeluluDetox"` (yes/no).
    - Primary button tap → DeluluDetox opens to HOME (not countdown, because no active session) (yes/no).
    - Screenshot attached.

    If Option B is too destructive for the user's device state, the user may skip SHL-02 and mark it as "deferred to real-world occurrence" — but SHL-02 remains a REQUIREMENT, so the SUMMARY must flag the skip as a gap for `/gsd-verify-work` to catch.
