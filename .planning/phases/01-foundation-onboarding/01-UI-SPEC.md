# Phase 1 — UI Design Contract

> Visual and interaction contract for the onboarding flow. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native iOS/SwiftUI -- shadcn not applicable) |
| Preset | not applicable |
| Component library | SwiftUI native components only |
| Icon library | SF Symbols (system, no third-party icon packs) |
| Font | San Francisco (system default via SwiftUI `Font` API) |

**Notes:**
- This is a native iOS app. No web component registries apply.
- All colors centralized in `Theme` enum backed by Asset Catalog named colors (D-09).
- All UI built with stock SwiftUI views and modifiers. Personality comes from copy, not custom widgets (D-10).

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|

| sm | 8pt | Compact element spacing, button internal padding |

## Typography

All sizes use the San Francisco system font via SwiftUI's `Font` API. Exact point values mapped to SwiftUI text styles:

| Role | Size | Weight | Line Height | SwiftUI Style |
|------|------|--------|-------------|---------------|
| Body | 17pt | regular (400) | 1.47 (25pt) | `.body` |
| Label | 15pt | regular (400) | 1.33 (20pt) | `.subheadline` |
| Heading | 22pt | bold (700) | 1.27 (28pt) | `.title2` |
| Display | 34pt | bold (700) | 1.18 (40pt) | `.largeTitle` |

**Rationale:** Using SwiftUI built-in text styles ensures Dynamic Type accessibility scaling for free. The two weights used are regular (400) for body/labels and bold (700) for headings/display. No custom fonts -- San Francisco is the platform standard and matches the clean/premium feel of D-08.

## Color

| Role | Value | SwiftUI Usage |
|------|-------|---------------|
| Dominant (60%) | `Color(.systemBackground)` -- white in light mode | Full-screen backgrounds for all three screens |
| Secondary (30%) | `Color(.secondarySystemBackground)` -- light gray in light mode | Card-like containers if needed; secondary text via `Color(.secondaryLabel)` |
| Accent (10%) | `#7C3AED` (electric violet) -- defined as `AccentColor` in Asset Catalog | See reserved-for list below |
| Destructive | `Color(.systemRed)` -- `#FF3B30` | Not used in Phase 1 (no destructive actions) |

**Accent reserved for (explicit list):**
1. "Grant Access" button fill on the onboarding screen
2. "Retry" button fill on the denial screen
3. "Choose Apps to Block" button fill on the home empty state
4. SF Symbol tint on all three screens (hero icons)
5. Navigation tint color (system back buttons, if any)

**Accent is NOT used for:** body text, backgrounds, borders, dividers, or decorative elements.

**Color rationale:** Electric violet (#7C3AED) was chosen because:
- Bold and high-contrast on white backgrounds (WCAG AA: 4.64:1 contrast ratio against white for large text)
- Playful and irreverent -- matches "DeluluDetox" brand energy (D-01)
- Distinct from corporate blue, medical green, or wellness pastels
- Works as a single strong brand color on clean white (D-08)

**Asset Catalog configuration for AccentColor.colorset:**
```json
{
  "colors": [
    {
      "color": {
        "color-space": "srgb",
        "components": { "red": "0.486", "green": "0.227", "blue": "0.929", "alpha": "1.000" }
      },
      "idiom": "universal"
    }
  ],
  "info": { "author": "xcode", "version": 1 }
}
```

**Dark mode:** Deferred. Phase 1 uses system semantic colors (`systemBackground`, `label`, `secondaryLabel`) which automatically adapt. The accent color is vibrant enough for both modes. Full dark mode theming is a future-phase concern.

## Screen Inventory

Phase 1 has exactly 3 screens. No navigation stack -- screens are swapped at the root level based on authorization state.

### Screen 1: Onboarding (ONB-01, ONB-02)

**Purpose:** Explain why Screen Time permission is needed, then trigger the system authorization prompt.

**Layout (top to bottom):**
1. Vertical center group (centered in safe area):
   - SF Symbol: `lock.iphone` at 72pt, rendered in accent color, `.symbolRenderingMode(.hierarchical)`
   - 16pt spacer
   - Headline (Display): "Your Phone Is Winning"
   - 8pt spacer
   - Subtext (Body, secondary color): "DeluluDetox needs Screen Time access to block distracting apps. No data leaves your device -- ever."
   - 32pt spacer
   - Primary CTA button: "Grant Access" (full-width, accent fill, white text, 50pt height, 12pt corner radius)
2. Bottom padding: 48pt from bottom safe area

**Interactions:**
- Tap "Grant Access" -> ViewModel calls `requestAuthorization(for: .individual)` -> system Face ID/passcode prompt appears
- While requesting: button shows `ProgressView()` spinner, button disabled
- On success: root ViewModel transitions to Home screen with `.opacity` transition (D-07)
- On denial: root ViewModel transitions to Denial screen

**States:**
- Default: button enabled, no spinner
- Requesting: button disabled, spinner replaces button label
- Error (simulator): handled silently by ViewModel, logs to OSLog

### Screen 2: Denial (ONB-03)

**Purpose:** Non-dismissible screen shown when user denies Screen Time permission. The denial screen IS the app (D-04, D-05).

**Layout (top to bottom):**
1. Vertical center group (centered in safe area):
   - SF Symbol: `hand.raised.fill` at 72pt, rendered in accent color
   - 16pt spacer
   - Headline (Display): "Nice Try"
   - 8pt spacer
   - Subtext (Body, secondary color): "DeluluDetox literally cannot work without Screen Time access. That's like hiring a bouncer and not letting them in the club."
   - 32pt spacer
   - Primary CTA button: "Let's Try Again" (full-width, accent fill, white text, 50pt height, 12pt corner radius)
2. Bottom padding: 48pt from bottom safe area

**Interactions:**
- Tap "Let's Try Again" -> re-triggers `requestAuthorization(for: .individual)`
- While requesting: button shows spinner, button disabled
- On success: transitions to Home screen
- On denial again: stays on this screen (no change)
- This screen cannot be dismissed, swiped away, or navigated from (D-05)

**States:**
- Default: button enabled
- Requesting: button disabled, spinner

### Screen 3: Home Empty State (D-06)

**Purpose:** Landing screen after successful authorization. Shows empty state since no apps are blocked yet.

**Layout (top to bottom):**
1. Navigation title: "DeluluDetox" (large title style, `.navigationBarTitleDisplayMode(.large)`)
2. Vertical center group (centered in remaining space):
   - SF Symbol: `apps.iphone` at 56pt, rendered in `Color(.tertiaryLabel)` (muted)
   - 16pt spacer
   - Heading (Heading): "No Apps Blocked Yet"
   - 8pt spacer
   - Subtext (Body, secondary color): "Pick the apps that steal your time. We'll do the rest."
   - 32pt spacer
   - Primary CTA button: "Choose Apps to Block" (full-width, accent fill, white text, 50pt height, 12pt corner radius)
3. Bottom padding: 48pt from bottom safe area

**Interactions:**
- Tap "Choose Apps to Block" -> No-op in Phase 1 (Phase 2 wires this to FamilyActivityPicker)
- Button is visually active but action is stubbed

**States:**
- Default: empty state visible, CTA button enabled
- Future (Phase 2+): this screen will show a list of blocked apps when selections exist

## Transitions & Animation

| Trigger | Animation | Duration | SwiftUI |
|---------|-----------|----------|---------|
| Authorization granted -> Home | Opacity crossfade | 0.35s | `.transition(.opacity)` with `withAnimation(.easeInOut(duration: 0.35))` |
| Authorization denied -> Denial | Opacity crossfade | 0.35s | Same as above |
| Button loading state | Implicit animation | system default | `withAnimation { isRequesting = true }` |

No celebration animations, no confetti, no bounces (D-07). Transitions are subtle and quick.

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| Dynamic Type | All text uses SwiftUI `.font()` text styles -- scales automatically |
| VoiceOver | All interactive elements have semantic labels; SF Symbols have `.accessibilityLabel()` |
| Minimum touch target | All buttons 44pt minimum height (primary buttons are 50pt) |
| Color contrast | Accent #7C3AED on white meets WCAG AA for large text (4.64:1); body text uses `Color(.label)` which is system-managed for contrast |
| Reduce Motion | Crossfade transition respects `UIAccessibility.isReduceMotionEnabled` -- use `.animation(.easeInOut(duration: 0.35), value:)` which SwiftUI auto-adjusts |

## Theme Implementation Contract

The executor MUST create `Theme.swift` as the single source of truth for all color values (D-09).

```swift
// DeluluDetox/Sources/DesignSystem/Theme.swift
import SwiftUI

enum Theme {
    static var accent: Color { Color("AccentColor") }
    static var background: Color { Color(.systemBackground) }
    static var primaryText: Color { Color(.label) }
    static var secondaryText: Color { Color(.secondaryLabel) }
    static var tertiaryText: Color { Color(.tertiaryLabel) }
}
```

**Rules:**
- No view may use `Color.purple`, `Color.blue`, or any raw color literal
- All color references go through `Theme.*`
- `AccentColor` in Asset Catalog is the single definition of the brand color
- System semantic colors (`systemBackground`, `label`, etc.) are accessed via `Theme` for discoverability, even though they could be used directly
