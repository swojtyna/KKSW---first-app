## 2. Key patterns to replicate

### 2.1 DIContainer register vs resolve, scope'y

Z `to_integrate/DependencyInjection/DIContainer.swift` (po przeniesieniu: `DeluluDetox/Sources/Core/DependencyInjection/DIContainer.swift`), linie 36–55 i 61–89:

```swift
public func register<T: Sendable>(
    _ type: T.Type,
    scope: ObjectScope,
    factory: @escaping @MainActor (DIContainer) -> T
) {
    // ... lock + wrap factory in MainActor.assumeIsolated + store
}

public func resolve<T>(_ type: T.Type = T.self) -> T {
    // ... lock + cache hit / factory / cache-if-application / fatalError if missing
}
```

Kluczowe własności do zapamiętania przez plannera:
- Factory jest `@MainActor` — VM można tworzyć bez problemu, `MainActor.assumeIsolated` odpowiada za concurrency.
- Brak rejestracji → `fatalError("📛 DIContainer: \(key) not registered. Check Injection files.")` (linia 68). Fail-fast zgodnie z D-21.
- `reset()` (linia 92) używany wyłącznie w testach (D-29).

### 2.2 `@LazyInjected` w `@Observable` ViewModelu

Z `.claude/guides/architecture/GUIDE.md` (linie 80–97) + `.claude/guides/dependency-injection/GUIDE.md` (linie 117–135). **Brak analogu w bieżącym kodzie** — Phase 1 używa init injection dla VM. To wzorzec docelowy fazy 01.1:

```swift
@MainActor
@Observable
final class OnboardingViewModel: @unchecked Sendable {

    @ObservationIgnored
    @LazyInjected private var requestAuth: RequestScreenTimeAuthUseCase

    private(set) var status: ScreenTimeAuthStatus?
    private(set) var isRequesting = false

    // init() bezargumentowy — D-16
}
```

Uwagi dla plannera:
- `@ObservationIgnored` **obowiązkowo** przed `@LazyInjected` — inaczej każdy dostęp do UC unieważnia observation.
- `@MainActor` + `@unchecked Sendable` to duet wymuszony przez `@Observable` (guide linia 83).
- Dla `AppRootViewModel` obok `@LazyInjected` dochodzi `@ObservationIgnored private var cancellables: Set<AnyCancellable> = []` (D-10).

### 2.3 `<Feature>Injection.register(in:)` shape

Z `.claude/guides/dependency-injection/GUIDE.md` (linie 80–98 i 336–349). **Brak analogu w kodzie** — pierwszy taki plik powstaje w 01.1:

```swift
// Features/Onboarding/Injection/OnboardingInjection.swift

enum OnboardingInjection {
    static func register(in container: DIContainer) {
        container.register(ScreenTimeAuthRepository.self, scope: .application) { _ in
            ScreenTimeAuthRepositoryImpl()
        }
        container.register(RequestScreenTimeAuthUseCase.self, scope: .unique) { c in
            RequestScreenTimeAuthUseCaseImpl(repository: c.resolve())
        }
        container.register(ObserveScreenTimeAuthStatusUseCase.self, scope: .unique) { c in
            ObserveScreenTimeAuthStatusUseCaseImpl(repository: c.resolve())
        }
        container.register(RefreshScreenTimeAuthStatusUseCase.self, scope: .unique) { c in
            RefreshScreenTimeAuthStatusUseCaseImpl(repository: c.resolve())
        }
    }
}
```

Konwencja: `enum` (caseless namespace — guide używa dokładnie tej formy), `static func register(in:)`, scope `.application` dla repo, `.unique` dla UC (D-22). Wewnątrz można rozdzielać na prywatne `registerRepositories(in:)` / `registerUseCases(in:)` — to jest Claude's discretion.

### 2.4 `CurrentValueSubject` + `eraseToAnyPublisher()` w repository

**Brak analogu w kodzie** — Phase 1 Repository (`ScreenTimeAuthRepositoryImpl.swift`, linie 1–11) eksponuje tylko synchroniczne `authorizationStatus`. Wzorzec docelowy (D-07/08, przykładowy kod; implementator domknie):

```swift
import Combine
import FamilyControls

final class ScreenTimeAuthRepositoryImpl: ScreenTimeAuthRepository, @unchecked Sendable {
    private let statusSubject: CurrentValueSubject<AuthorizationStatus, Never>

    var statusPublisher: AnyPublisher<AuthorizationStatus, Never> {
        statusSubject.eraseToAnyPublisher()
    }

    init() {
        self.statusSubject = CurrentValueSubject(AuthorizationCenter.shared.authorizationStatus)
    }

    func requestAuthorization() async throws {
        try await AuthorizationCenter.shared.requestAuthorization(for: .individual)
        statusSubject.send(AuthorizationCenter.shared.authorizationStatus)
    }

    func refreshStatus() {
        statusSubject.send(AuthorizationCenter.shared.authorizationStatus)
    }
}
```

Protokół w tym samym pliku (feature-structure GUIDE linia 98–99, 105–111):

```swift
protocol ScreenTimeAuthRepository: Sendable {
    var statusPublisher: AnyPublisher<AuthorizationStatus, Never> { get }
    func requestAuthorization() async throws
    func refreshStatus()
}
```

Dlaczego Combine, nie AsyncStream: D-09/12 — `CurrentValueSubject` jest multi-subscriber i trzyma ostatnią wartość. `GetScreenTimeAuthStatusUseCase` **nie powstaje** (D-12).

### 2.5 `ObserveScreenTimeAuthStatusUseCase` (Combine publisher UC)

Najbliższy analog: `DeluluDetox/Sources/Domain/UseCases/RequestScreenTimeAuthUseCase.swift` (linie 1–17). Ten sam szkielet (protocol + Impl + init injection); różni się typ zwracany:

```swift
import Combine
import FamilyControls

protocol ObserveScreenTimeAuthStatusUseCase: Sendable {
    func callAsFunction() -> AnyPublisher<AuthorizationStatus, Never>
}

final class ObserveScreenTimeAuthStatusUseCaseImpl: ObserveScreenTimeAuthStatusUseCase {
    private let repository: ScreenTimeAuthRepository

    init(repository: ScreenTimeAuthRepository) {
        self.repository = repository
    }

    func callAsFunction() -> AnyPublisher<AuthorizationStatus, Never> {
        repository.statusPublisher
    }
}
```

`RefreshScreenTimeAuthStatusUseCase` analogicznie, tylko `func callAsFunction()` → `repository.refreshStatus()` (D-13).

### 2.6 `@CasePathable enum Destination` + case-path bindings

Z `.claude/guides/navigation/GUIDE.md` (linie 46–64 i 76–92). **Brak analogu w kodzie** — Phase 1 `AppRootView.swift` używa `Group { switch }` nad `model.screen` (linie 8–19). Po refaktorze (D-02, D-04):

```swift
import Observation
import Combine
import SwiftUINavigation

@MainActor
@Observable
final class AppRootViewModel: @unchecked Sendable {

    @CasePathable
    enum Destination {
        case onboarding
        case denial
        case home
    }

    var destination: Destination?

    @ObservationIgnored @LazyInjected private var observeStatus: ObserveScreenTimeAuthStatusUseCase
    @ObservationIgnored @LazyInjected private var refreshStatus: RefreshScreenTimeAuthStatusUseCase
    @ObservationIgnored private var cancellables: Set<AnyCancellable> = []

    init() {
        observeStatus()
            .sink { [weak self] status in
                self?.destination = Self.map(status)
            }
            .store(in: &cancellables)
    }

    func onScenePhaseActive() {
        refreshStatus()
    }
}
```

**Uwaga na różnicę od navigation/GUIDE.md Wzorzec A:** ten enum **nie** trzyma VM w case (por. guide linie 50–64, które pokazują `case addItem(AddItemViewModel)`). D-02 mówi wprost: "Enum bez payloadu VM — to zasadnicza różnica od wzorca modal". To jest nowy **Wzorzec B** (D-24), który ten plan do guide'a dopisuje.

View-side (tylko wzorzec; przykład odpowiadający feature-first-owi):

```swift
struct AppRootView: View {
    @Bindable var model: AppRootViewModel
    @Environment(\.scenePhase) private var scenePhase

    var body: some View {
        // jedno z możliwych rozwiązań; planner dopnie szczegóły
        // (switch na destination lub dedykowane swift-navigation API)
        // Dla enum bez payloadu — zwykły switch + .animation(value: model.destination)
        // jest akceptowalny (guide Wzorzec B)
        // ...
        .onChange(of: scenePhase) { _, newPhase in
            if newPhase == .active { model.onScenePhaseActive() }
        }
    }
}
```

Uwaga: swift-navigation Wzorzec A (`sheet(item: $model.destination.addItem)`) jest dla prezentacji **modal**. Tu (root-level switch), `@CasePathable` daje darmowe case-path bindings; planner może użyć switch nad `destination` lub `.ifCaseLet`/innych API paczki, zależnie od ostatecznej decyzji w D-24.

### 3.2 Pułapki koncepcyjne (nie trivialne syntax)

- **`@ObservationIgnored` przed `@LazyInjected`** — łatwo zapomnieć; bez tego każdy dostęp do UC invaliduje observation (CONTEXT D-10).
- **Destination enum bez payloadu** — nie próbuj używać `.sheet(item: $model.destination.onboarding)` tak jak w navigation/GUIDE.md Wzorzec A. Tam case trzyma VM; tu nie. Dla Wzorca B root-level switch wystarczy zwykły `switch model.destination` lub `switch` z `if-case-let` wspieranym przez `@CasePathable` (ostateczna forma po aktualizacji navigation/GUIDE.md per D-24).
- **Scope `.application` vs `.unique`** — Repo MUSI być `.application` (trzyma stan `CurrentValueSubject`). UC MUSI być `.unique` (bezstanowe, cheap, kilka miejsc konsumentów). VM **nie rejestrowane** (D-22).
- **`DIContainer.reset()` w `setUp`, nie `tearDown`** — kontrakt testu jest: "zaczynam z pustego" (guide linia 291). Jeśli zapomnisz, test X zobaczy rejestracje z testu W.
- **`@LazyInjected` łapie `DIContainer.shared` w momencie pierwszego dostępu** — jeśli test tworzy VM przed rejestracją mocków, pierwszy dostęp do UC leci do containera bez mocków → fatalError albo rzeczywisty impl. Kolejność w teście: `reset()` → `register(mock)` → `vm = VM()` → akcja na VM.
