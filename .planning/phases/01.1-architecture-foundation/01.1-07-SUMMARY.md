## D-17 Common/ reconciliation note

`01.1-CONTEXT.md` D-17 used the vocabulary "Common/" to describe shared-ownership semantics. Phase 01.1 shipped the **Simple layout variant** per `feature-structure/GUIDE.md` — i.e. `Features/Onboarding/{Repository,UseCase}/` with no `Common/` subdir. Ownership invariant is preserved:

- Onboarding is the feature-owner of `ScreenTimeAuth*`.
- Denial + Root consume only the UseCases (never the Repository directly).
- `OnboardingInjection.swift` is the single place `ScreenTimeAuthRepositoryImpl` is registered.

Both layouts honor the "shared → feature-owner" rule; the `Common/` terminology in CONTEXT is a description, not a filesystem requirement.
